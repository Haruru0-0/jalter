# Features built (Phase 1, plus moderation from Phase 2)

Branch at seeding time: `autorole-upgrade`. Most features are off by default; admins enable them. Setup replies are ephemeral and need Manage Server or the bot manager role.

- **Panel** `/panel overview`, `/panel manager-role` (always on).
- **Language** en / fr / ar per server (always on).
- **Media** `/media add`; only `/media add` registers an image, not uploading to the storage channel.
- **Embeds** `/embed create|edit|show`; use in text with `{embed:name}` (always on).
- **Post** `/post text|buttons`, mentions blocked, user must see and send in the channel (always on).
- **Greet / leave / boost** `/set ...` and `/test`; optional card image and DM (greet, boost). Retries as plain text if Discord rejects the embed.
- **Autorole** `/autorole add|remove|show|disable`, `timed add|remove` (delay 1m-30d; granted by the shared scheduler, job type `autorole.grant`, see [[architecture]]), `reassign on|off` (30-day sticky roles), `blacklist add|remove`. See [[decisions]].
- **Logging** `/logging set|clear|event|ignore|unignore|prefix-add|prefix-remove|setup|export|import|status` plus enable/disable. 24 events in categories default, messages, members, join, server, voice, mod; `event` toggles one or `all`. Ignore lists (channels, members, prefixes) apply to message events only. Ban, unban, timeout, channel and role create/delete and some message deletes add a "By" field from the audit log (only if the entry is under 10 s old; no View Audit Log means no field, not an error). Voice logs only join, move, leave (mute/deafen logs nothing). `setup` makes a private "Logs" category with five channels; running it again makes new ones and leaves the old. `export`/`import` carry disabled events and prefixes only. The `mod` category receives the moderation case log through a hidden `modAction` event (see Moderation). Code in `src/features/logging/`. See [[gotchas]], [[roadmap]].
- **Info** `/userinfo`, `/avatar`, `/banner`, `/serverinfo`.
- **Help** `/help [feature]` (always on, open to everyone). Overview lists each feature with its on/off state and top-level commands, plus the "coming soon" names. `/help <feature>` lists every runnable command path with its description. Built from `FEATURES` and the loaded commands' JSON, so new commands show up without editing help. Uncommitted at last check (branch `autorole-upgrade`).
- **Moderation** (Phase 2 steps 1 and 2, branch `phase-2`; off by default, `/moderation enable`). Actions: `/warn`, `/timeout` (default length from settings, max 28 days), `/untimeout`, `/mute` and `/unmute` (mute role), `/kick`, `/ban` (optional `delete_days` 0-7, default from settings) and `/unban`. All take `user` and `reason` (max 400 chars); `/timeout`, `/mute`, `/ban` take an optional `duration` (1 minute minimum, 10 years maximum, max 32 characters; `/mute` and `/ban` are permanent without one). Every successful action creates a per-server numbered case (`mod_cases`) and posts an embed to the `mod` log. `/warnings list|edit|delete|clear|top` (a warning's id is its case number; delete/clear mark inactive, nothing is posted to the mod log; a member may list their own) and `/reason case reason` (any case type; also edits the stored mod log message). Settings `/moderation status|reason-required|dm|timeout-default|ban-delete-days|mute-role [apply]|permitted-role-add|permitted-role-remove` (defaults: reasons required, DMs on, 10m timeout, 0 delete days, max 10 permitted roles; a permitted role may use every moderation command whatever its Discord permissions). Timed ban and mute end by themselves via scheduler jobs `mod.unban` and `mod.unmute` and record an "expired" unban/unmute case. A member who rejoins while muted gets the mute role back (`GuildMemberAdd`, only when the feature is on). Needs the bot to have Kick Members, Ban Members, Moderate Members and Manage Roles. Code in `src/features/moderation/`. See [[architecture]], [[decisions]], [[gotchas]].
