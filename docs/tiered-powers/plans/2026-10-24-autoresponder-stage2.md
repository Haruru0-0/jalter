# Autoresponder Stage 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use tiered-powers:subagent-driven-development (recommended) or tiered-powers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scripts can use random values (`{range}`, `{choose}`, `{weightedchoose}`, `{lockedchoose}`), the words after the trigger (`[$N]`, `[$N+]`, `[$N-M]`, `{requirearg}`) and role targets, in the text editor and in the interactive builder.

**Architecture:** The parser learns the exact bracket tokens; the compiler turns them into template parts plus a stored random spec and argument checks (`compiled.version` 2; version 1 rules keep running); the message handler computes the words and draws every random value once, and passes both through `evaluate` and `executePlan`; the dry run, Try it and the builder reuse the same functions. Pure parts (tokens, words, drawing) are injectable and carry the tests.

**Tech Stack:** Node 22 ESM, discord.js 14.27, Postgres, `node --test`.

**Spec:** `docs/tiered-powers/specs/2026-10-24-autoresponder-stage2-design.md` (its "calls made after the builder check" are binding). Parent: `2026-10-24-autoresponder-design.md`; builder: `2026-10-24-autoresponder-builder-design.md`.

## Global Constraints

- Node 22+, ESM, discord.js 14.27.0, no new dependency, no new intent. No migration unless Task 2 proves one is needed (the stored `compiled` JSON gains fields).
- Every user-facing string in `src/i18n/en.json`, `fr.json`, `ar.json` (real translations; `test/i18n.test.js` checks parity). New compile error codes join `COMPILE_ERROR_CODES` and each gets `autoresponder.error.<CODE>`; new run-time codes join `RUN_ERROR_CODES` and each gets `autoresponder.run.<CODE>`; the loop tests in `autoresponder-commands.test.js` enforce both.
- Only these brackets are tokens: `[$N]`, `[$N+]`, `[$N-M]` and `[range]`, `[choice]`, `[lockedchoice]` with optional `2` to `4` (`[range2]` ...). Every other `[...]` is plain text; `\[` stays a literal bracket, in text and in arguments. A random token is live only if the script has the function that produces it; otherwise it stays literal text. `[$N]` forms are always tokens. N is 1 to 20.
- Words: `startswith` and `includes` rules only (after the trigger; for `includes`, after its first occurrence, found case-insensitively in the original text; whitespace-split; leading whitespace ignored; no word boundary, so `!sayhello` gives word 1 `hello`). `exact`, `endswith`, `regex`: no words.
- Random: `range` up to 4 (`min-max`, whole numbers, either may start with `-`, each at most 1,000,000,000 in size, min <= max); `choose` and `weightedchoose` share one list of up to 4, numbered in script order; `lockedchoose` (up to 4): the nth pairs with the nth chooser, option counts must match, none without a partner (`CHOICE_NOT_CHOSEN_YET`); `weightedchoose` weights are non-negative integers or decimals with a `%` suffix, not all zero. All values drawn once per message, before rendering.
- `{requirearg:N}` / `{requirearg:N|type}` (types `user`, `channel`, `role`, `color`, `number`); `number` = optional `-`, digits, optional decimal part; `user` = `<@id>`, `<@!id>` or bare id of a current member, checked when the rule runs; `channel`/`role` = mention or bare id of an existing one; `color` = `#rrggbb`. A failed `requirearg` skips the rule with one `autoresponder.notice.arg` notice (position and expected type; throttled like other notices; none under `{silent}`). `{requirearg}` in a mode without words is the hard error `NO_ARGUMENTS_IN_MODE`; a `[$N]` there is only a warning.
- Role targets: `{addrole:role|[$N]}` / `{removerole:role|[$N]}` only where the script has `{requirearg:N|user}`; the script must also contain a `{requirerole}` or `{requireperm}` (presence check only); counts toward the 3 role/nickname actions; at run time the target must be a current member the bot can manage (not above the bot, not the owner) and the role must pass `isDangerousRole` and `botCanGive`; a refused change is skipped and the rest runs.
- Pings: only the triggering member (`{user}`), users the writer typed in the script text, `{server_owner}`, and words checked as `user` by `requirearg` may be pinged; never roles, `@everyone`, `@here` or any other member-typed mention.
- Stage 1 rules (`compiled.version` 1) keep running unchanged; `/autoresponder test` and Try it use the same words/drawing code as the live handler and show drawn values and the ping list.
- Tests hit the DB (`npm test`, concurrency 1; run one test process at a time). Commit style `feat(autoresponder): ...`, the user's own git name and email, no Co-Authored-By Claude trailer. Never stage `docs/memory/roadmap.md`, `docs/memory/.obsidian/workspace.json` or `test/features/automod-*.test.js` (the user's uncommitted edits).

## Review Focus

1. Old text is unchanged: `[Note]`, `[range]` in a script with no `{range}`, `\[range]`, and a stored version 1 rule all still render and run exactly as before (Tasks 1, 2, 3).
2. Member-typed text never pings: `@everyone`, a role mention, or a user mention in `[$1]` without `{requirearg:1|user}` is shown but not pinged; with the check only that user is pinged (Task 3).
3. Role-target abuse: an unchecked word as target, a missing gate, a target who left, is above the bot, or is the owner, a role that became dangerous: refused at save or skipped at run with one error line while the rest runs (Tasks 2, 3).
4. Every random value is drawn once and agrees across text, nickname and embed; bad ranges, weights, counts and pairings are save-time errors (Tasks 1, 2).
5. Words edge cases: `!SAY  Hello`, `!sayhello`, tabs/newlines, a 2000-character message, more than 20 words, an escaped `\[$1]` in text and in an argument (Task 1).

### Task 1: Pure core - bracket tokens, words, random drawing

**Files:**
- Create: `src/features/autoresponder/script/args.js`, `src/features/autoresponder/script/random.js`
- Modify: `src/features/autoresponder/script/parse.js`, `src/features/autoresponder/match.js`
- Test: `test/features/autoresponder-tokens.test.js`, `autoresponder-args.test.js`, `autoresponder-random.test.js`; the existing parse and match tests must pass unchanged

**Tier:** sonnet - grammar change to a tested parser, escape rules, pure helpers with many edge cases

**Interfaces:**
- Produces in `parse.js`: text nodes may now be followed/preceded by token nodes `{ t: 'arg', from: number, to: number | 'end', pos: number, raw: string }` (`[$N]` -> from N to N; `[$N+]` -> to `'end'`; `[$N-M]`) and `{ t: 'rand', kind: 'range'|'choice'|'lockedchoice', n: number, pos: number, raw: string }` (`n` 1 to 4). Recognized by one anchored regex at an unescaped `[` in text; anything else (`[Note]`, `[$0]`, `[$21]`, `[range5]`, `[$3-2]`) stays literal text. `\[` still produces a literal `[` that is never tokenized. In call arguments, brackets stay plain text but an escaped `\[` must survive as a literal: represent it with a private-use sentinel `` in the stored argument string, exported as `ESCAPED_BRACKET`, so later rendering can tell `\[$1]` from `[$1]`. `PARSE_ERROR_CODES` unchanged.
- Produces in `match.js`: `triggerRemainder(rule, text): string | null` - for `startswith` and `includes` rules the original text after the trigger (case-insensitive search, first occurrence for `includes`, message trimmed at the start); `null` for `exact`, `endswith`, `regex`. `matchRule` and `chooseRule` behave exactly as before.
- Produces in `args.js`: `MAX_ARG_INDEX = 20`; `parseWords(remainder: string | null): Words` with `Words = { list: string[], rest(n: number): string }` (whitespace split into `list`; `rest(n)` is the original text from word n on, original spacing kept; empty list for null); `renderArg(token, words: Words): string` (`[$N]` -> word or `''`; `[$N+]` -> `words.rest(N)`; `[$N-M]` -> words N to M joined by one space); `renderArgsInText(text: string, words: Words): string` (renders `[$...]` tokens appearing inside an argument string such as a nickname, maps `ESCAPED_BRACKET` back to `[`); `checkArgType(type: 'user'|'channel'|'role'|'color'|'number'|null, word: string | undefined, guild): Promise<{ ok: boolean, id?: string }>` (user: mention or id, member fetched from `guild.members`; channel/role: mention or id present in the guild caches; color `#rrggbb`; number as in Global Constraints; `null` type = the word merely exists).
- Produces in `random.js`: `drawRandom(spec, rng = Math.random): Draws` with `spec = { ranges: [{ min, max }], choosers: [{ kind: 'choose', options: string[] } | { kind: 'weighted', weights: number[] }], locked: string[][] }` and `Draws = { range: number[], choice: (string | number)[], lockedchoice: string[], picked: number[] }`; `weightedPick(weights, rng): number` (index; relative weights); `renderRand(token, draws): string` (empty string when the index has no draw). A weighted chooser's `choice` is its 1-based position; a `locked` list pairs with the chooser of the same index.
